# v0.2-named：全域命名版

## 本轮交付

县表1195行、县际距离表3413行。原有1171个区域代号县名全部替换；24个历史启发锚点也按同一规则复核。名称分为：

|名称依据|数量|
|---|---:|
|有资料支持、保留的古名|4|
|现代汉字地名回退|1183|
|现代地名原文回退|8|

保留古名为洛邑、蓟、临淄、曲阜。其证据范围见`sources/historical_name_review.json`；保留蓟这个古名不等于确认前770年燕已迁都至此。

本轮1190行县名发生变化，另5行显示名称不变，但同样补充了来源。未保留的古名仅表示本轮没有完成所需考证，不构成否定该古名的结论。

现代地名可以是现代区县、城镇、聚落或自然地理名称，不限定必须为现行县名。所有1195个现代命名参考点均在对应游戏分区内，离原游戏治所最远45.602公里。该距离是核对参考，不是县际道路距离。重名允许存在，关联仍以唯一县编号为准，不为凑唯一性编造新地名。

8个暂无可用汉字别名的参考名保留原文：Qalgar、Jagt、Tulantai、Tariat、Sain Us、Yaksal-li、Sangejing、Kubqi Shamo。没有自行编造汉译名。

## 选名方法

从GeoNames的CN、KP、MN公开快照读取WGS84地名点和带语言标签的别名。排除标记为历史名称、俗称或使用期已结束的别名。优先选县内汉字地名，再按首府、地级城市与县域中心、县治、乡镇、聚落、地形层级选择；同级采用离游戏治所较近者。

首轮会冻结每个县实际使用的来源条目、GeoNames编号、URL、现代参考点、源数据修改日期、原始下载文件SHA-256和原型县名。以后从该冻结对照离线重建，不会因在线地名库更新而偷偷改名。

来源地名中的国家代码仅用于溯源，不用于前770年国家归属。数据源不保证名称始终为官方现行名称，也不证明这些现代聚落在前770年已存在。

## 与前版兼容

县编号、县界、治所坐标、总面积、地形、初始人口、七类土地用途、自然资源、所属国家、所属郡均不变。距离表仍有3413条陆路、140对双向水路，水路与陆路可以共存；未配置水路仍为null，不变为0。

治所仍是原型游戏节点，不能把现代命名参考点当作古代真实治所。县界也仍是游戏分区，不是这些现代行政单位的真实边界。

构建流程检查完整两表契约、县界拓扑、地名来源、历史别名过滤、改名前后非名称字段、距离表字节一致性及重建一致性。结果写入data中的validation_report、test_report和reproducibility_report。

## 读取与复现

运行时使用`data/counties.json`及`data/connections.json`。县表的`资料依据.地名考证`内已有命名类别、现代参考名、参考点与URL；无须增加第三张运行时表。`sources/modern_name_crosswalk.json`是构建输入，`data/name_changes.csv`是审计日志。

```bash
python -m pip install -r requirements.txt
python scripts/build_map.py
python scripts/enrich_names.py
python scripts/validate.py
python -m unittest discover -s tests -v
```

## 尚未改变的内容

本轮集中完成可用地名，不以现代名称替代历史论证。国家归属、矿产配置、人口土地估计、地形与古代交通仍沿用v0.1设计参数；地图外缘仍是设计外框。下一轮校核这些项目时继续保留稳定编号，不把游戏数值包装为史料。

GeoNames数据使用CC BY 4.0；逐县来源和署名方式见`NOTICE.md`。本版Excel与数据包在对话中交付，JSON/CSV及完整生成输入同时保存在仓库。
