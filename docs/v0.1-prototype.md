# v0.1-prototype：全域工程原型

**这是按两表契约生成的游戏工程原型，不是已经考证完成的前770年历史地图。**

本次仓库提交包含生成器、冻结输入、校验器、15项回归测试及依赖。已生成的数据文件随对话附件交付；仓库中的完整数据可以用以下命令重建。

```bash
python -m pip install -r requirements.txt
python scripts/build_map.py
python scripts/validate.py
python -m unittest discover -s tests -v
```

建议 Python 3.11 或更新版本。安装依赖后，生成过程只使用仓库中的冻结输入，不需要联网查询地图服务。

## 已生成的规模

- 县表：1,195行。
- 县际距离表：3,413行；每对县只出现一次。
- 陆路：3,413对；均按双向共用距离处理。
- 水路：140对；本版均为双向且物理距离相同。代码与测试支持仅单向有通道的情况。
- 历史启发的地点锚点：24个；多数尚未逐条核验。
- 区域代号县名：1,171个，不能作为古县名使用。
- 设计外框内模型面积：318,878,047.82公顷。
- 模型人口：10,915,293人。该数字不是历史人口估计或史料统计。

## 输出

`data/counties.json`与`data/connections.json`是正式两表结构。`县表.csv`、`县际距离表.csv`是对应CSV表示；嵌套字段以JSON文本放在单元格中。`counties.geojson`复用同一县表几何与属性，不是第三张游戏基础表。`manifest.json`记录版本、参数、来源和局限；`validation_report.json`记录校验结果。

对话中的Excel有两个工作表。为了阅读，县表将治所经纬度、七类土地用途及国家/郡展开为独立列；JSON仍保留用户指定的嵌套结构。Excel数据表头在第4行，数据从第5行开始。CSV是第1行表头。

## 空值与距离

JSON的`null`和CSV空单元格表示本剧本没有该通道，绝不表示零公里。无陆路时通行类型也必须为`null`。资源空列表`[]`表示本版没有配置资源，不是地质普查中确认不存在任何矿产。

水路距离是同一县级水运节点之间、仅经这两个县的河网物理长度。一个县内不连通的河道不能自动换乘。陆路、车行、水路分别建图；本版不把陆水转换当作零成本操作。顺逆流速度、季节影响和港口接驳成本应在移动系统中另行处理，不能混进公里数。

## 校验结果

字段、主键、县对唯一性、外键、枚举、正距离/null语义、七项面积精确闭合、椭球面积、有效多边形、治所位于县界内均通过。分区之间面积重叠为0，设计外框未覆盖面积为0；投影往返产生约0.0022平方米的边缘数值误差。陆路图为一个连通分量，无孤立县。15项回归测试通过，包括单向水路、交换A/B时交换方向、禁止0替代null和无车道路过滤。

这些检查只证明结构和算法一致，不证明历史准确。

## 尚未完成的历史工作

1. 地图外缘是覆盖东周活动区及缓冲边地的设计外框，尚未核定为完整历史范围。海岸来自本地Natural Earth 1:1.1亿低分辨率数据，不是前770年海岸。
2. 县界由固定种子Voronoi分区生成，不是古县界；地形由粗略设计区域生成，未使用DEM。
3. 人口、土地用途、国家核心区半径和道路绕行系数都是公开的游戏设定。郡全部未设置；未分配国家不表示无人区。
4. 河道为手工概化线，并未验证实际古代通航条件。黄河下游采用向河北北流的示意走廊，而非现代山东入海线路。
5. 资源仅有按地形设置的石料/陶土及铜绿山概位示例，未完成全域矿产整理。某遗址在春秋战国被开采，不等于已证明前770年开采。
6. 楚丹阳、郑迁徙、燕迁蓟及巴蜀吴越开局地点与归属等，需要逐条校核，不得把本版占位数据直接提升为史实。

完整来源及每项来源能支持/不能支持的范围在`sources/scenario_bundle.json`的`sources/catalog.json`条目内。输入包中的键是逻辑文件路径；生成器也支持将这些条目拆成同路径独立JSON文件。

县编号依照固定地点编号或网格坐标生成，不按县名或国家重新排序编号。已有编号消失时重建会报错；改变分辨率或重新分区前必须提供明确的编号迁移方案。不要删除编号登记文件来绕过检查。
